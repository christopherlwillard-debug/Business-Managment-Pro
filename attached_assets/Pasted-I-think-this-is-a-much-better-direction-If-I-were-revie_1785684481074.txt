Future-proof it

One thing I'd add to the issue is a "Custom Block" placeholder, even if it's hidden for now.

Eventually users will want things like:

Google Reviews
Newsletter signup
Financing badge
QR code
"Download Our Brochure"
Embedded Google Map
Recent blog posts
Awards & certifications

If the footer is built around generic blocks instead of four hardcoded column types, all of those become easy additions later.

I'd also add these acceptance criteria
✔ Columns can be resized (25/33/50/66/75/100% widths).
✔ Every visible footer element is directly clickable and inline editable.
✔ Hovering any block displays edit controls and highlights the selected block.
✔ Footer automatically stacks into a responsive layout on tablet and mobile, with configurable order.
✔ Footer templates can be swapped without losing existing content where possible.
✔ Copyright and legal links are rendered in a dedicated bottom bar, separate from the main content columns.

If you build it this way, I don't think you'll ever need to redesign the footer architecture again—only add new block types over time.
