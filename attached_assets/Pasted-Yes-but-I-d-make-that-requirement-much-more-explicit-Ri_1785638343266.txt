Right now your spec implies code reuse, but it doesn't require it. AI developers often default to rebuilding components because it's easier than integrating with existing ones.

I'd add one more section near the top.

Engineering Principles
Reuse Before Rebuild

BuildPro Studio 2.0 is a UX redesign, not a rewrite.

Before creating any new component, search the existing codebase for reusable functionality.

Prefer extending or restyling existing components over replacing them.

Only create new components when the current architecture cannot reasonably support the desired UX.

Examples:

✅ Reuse existing drag-and-drop engine.
✅ Reuse existing undo/redo system.
✅ Reuse existing auto-save logic.
✅ Reuse existing inline editing.
✅ Reuse existing website rendering engine.
✅ Reuse existing section template data.
✅ Reuse existing publish/save APIs.
✅ Reuse existing selection state.
❌ Do not create a second editor engine.
❌ Do not create a second website renderer.
❌ Do not duplicate existing state management.
❌ Do not replace working systems solely for cleaner code.
Minimize Technical Debt

Every change should reduce complexity rather than increase it.

If an existing component can be improved through refactoring instead of replacement, refactor it.

Avoid duplicate utilities, duplicate hooks, duplicate state stores, or parallel implementations.

Preserve Existing Functionality

Every feature that currently works must continue to work after the redesign unless explicitly listed in the task.

Visual redesigns must not introduce functional regressions.

Build Incrementally

Every milestone should leave Studio in a fully working state.

Avoid "big bang" rewrites.

Each completed milestone should be shippable on its own.
