2. Don't require idempotency

I would remove this:

The migration is fully idempotent (safe to run twice...)

Database migrations are normally not written to be run twice.

Instead I'd say:

The migration should be safe to run once against a production database currently at schema 0040.

That's the normal expectation.

If you force it to be idempotent, Replit will end up wrapping everything in IF EXISTS, IF NOT EXISTS, DO $$, etc., making the migration much more complex than necessary.
