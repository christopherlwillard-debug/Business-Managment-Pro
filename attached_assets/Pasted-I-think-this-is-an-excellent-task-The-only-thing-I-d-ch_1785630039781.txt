I'd rename it:

#1445 - Unified Receipt Intake & Robust PDF Processing

The feature is really about having one intake pipeline, not just one button.

Add one more "Done looks like"
✅ All receipt sources (camera, image upload, PDF upload, email attachment in the future, and drag & drop) use the exact same backend parsing pipeline so new intake methods require no additional parsing logic.

This prevents duplicate code from creeping in later.

I'd also tweak the PDF logic

Instead of:

if (text.length < 80) {
    // use Vision
}

I'd make it something like:

const hasEnoughText =
    extractedText.trim().length >= 80 &&
    extractedText.split(/\s+/).length >= 20;

if (!hasEnoughText) {
    // Vision fallback
}

Some receipts have only 60–70 characters but are perfectly valid.

Better error states

Instead of one generic message:

Failed to parse receipt.

Use distinct messages:

Unsupported file

We couldn't open this file.

Unreadable receipt

We could open the receipt, but couldn't read enough information.

AI extraction failed

The receipt was read, but we couldn't identify the vendor or totals. Please review before saving.

That makes troubleshooting much easier.
