#1032 - Fix MFH Data — Promote Brands to Builders
What & Why
The production MFH tables have the wrong data at every level. A one-time migration is needed to fix it before any more data is entered:

mfh_manufacturers contains "Clayton" — which is a dealer/client, not a home builder
mfh_models contains Southern, Giles, Norris, Champion, Tru, Addison, Appalachia, Middlebury, Rutledge, Wakarusa — these are home builders (brands), not floor-plan model names
Correct structure:

Builders (mfh_manufacturers): Southern, Giles, Norris, Champion, Tru, Addison, Appalachia, Middlebury, Rutledge, Wakarusa
Models (mfh_models): empty after migration — user enters actual floor plan names (Farmhouse, Magnolia, etc.) through the UI
Clayton: already in the clients table; must be removed from mfh_manufacturers
Done looks like
Home Library → Builders tab shows: Southern, Giles, Norris, Champion, Tru, Addison, Appalachia, Middlebury, Rutledge, Wakarusa
"Clayton" is gone from the Builders list entirely
Models tab is empty and ready for the user to add real floor plan names (Farmhouse, Magnolia, Breeze, etc.) under each builder
The Edit Job form Builder dropdown shows Southern, Giles, Norris, etc. — not Clayton
Any jobs that previously referenced the old wrong IDs have their mfh fields cleared (they can be re-applied correctly)
UI has brief helper text on the Builder dropdown: "who built the home (Southern, Giles, etc.)" so the distinction from Client is crystal clear
Out of scope
Entering the actual model/floor-plan names — the user does this through the UI after the migration
Any changes to the clients table
Steps
Write and trigger the migration — Add a new endpoint under admin/migrations that: a. Creates new mfh_manufacturers rows for each of the 10 current model names (Southern, Giles, Norris, Champion, Tru, Addison, Appalachia, Middlebury, Rutledge, Wakarusa) in both dev and production b. Deletes all rows from mfh_models c. Deletes "Clayton" (and any other non-builder entries) from mfh_manufacturers d. Sets mfhManufacturerId and mfhModelId to null on all jobs that referenced the old invalid IDs Trigger it via curl with MIGRATION_KEY against the production server.

Add UI helper text — On the Builder dropdown in both the Edit Job form and the MFH job card panel, add a short subtitle/hint: "the company that built the home — e.g. Southern, Giles" so it's immediately clear this is not the client/dealer.
