I would add one more Constitution rule because this is exactly the situation you're running into.

Rule 52 — One Engine, Many Workflows

Similar business workflows may require different inputs or outputs, but they must share the same underlying engine. Never duplicate an engine because two workflows are different. Instead, build one reusable engine that accepts configurable inputs and let each workflow consume its results differently.

Example:

Manufactured Home: Business → Job and Client → Job both use the same Distance Engine.
General Contracting: Business → Job uses the same Distance Engine.
Future modules (Supplier → Job, Warehouse → Job) must also reuse that engine.

I think that's the architecture you're actually aiming for, and it's much stronger than simply saying "there should only be one distance calculation." There should be one routing engine capable of calculating many different routes.
