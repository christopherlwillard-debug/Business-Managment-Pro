Additional issues found

1. Job Payroll can show the wrong job after fast navigation

JobPayroll.tsx starts several requests when the job ID changes but does not cancel or guard stale responses. If someone opens Job A and quickly navigates to Job B, Job A’s result can arrive afterward and overwrite Job B’s screen.

That can display the correct-looking financial data under the wrong job.

2. Job Payroll uses a different financial waterfall

Job Payroll calculates its own split income instead of using the canonical waterfall. It:

Removes mileage reimbursement from expenses before calculating the split pool.
Uses aggregate subLaborCost.
Does not consistently distinguish hourly, fixed, and allocation payouts.
Can disagree with Job Financials and the close-job flow.
This is a real financial-display inconsistency.

3. Route Planner’s total profit is incomplete

The Route Planner’s aggregate currently calculates:

total collected - total expenses
It omits subcontractor labor, allocation payouts, and other costs included in the canonical job profit result. Individual route stops and the route total can therefore disagree.

4. Closed Jobs CSV uses a separate outdated calculation

The on-screen Closed Jobs table uses the newer profit summary, but CSV export uses its own older arithmetic. The export can disagree because it omits or mishandles:

Hourly subcontractor labor
Fixed/allocation payroll
Accrued bonuses
Job-linked other income
Mileage reimbursement and fuel handling
Void filtering
Canonical expense exclusions
It also does not select jobNumber, so exported job numbers can fall back to internal IDs.

5. Drywall has a separate payroll-data mismatch

Drywall has a $320 hourly payment record with 16 work hours, but no corresponding job_sub_hours row. That is an undercount risk, not the cause of the negative value. It should be reviewed separately so the final correct profit includes the intended labor cost exactly once.

I have not changed production records or modified these additional paths yet. The original negative problem is mathematically isolated to cross-job batch contamination; these are other real areas that could produce inconsistent financial displays elsewhere.
