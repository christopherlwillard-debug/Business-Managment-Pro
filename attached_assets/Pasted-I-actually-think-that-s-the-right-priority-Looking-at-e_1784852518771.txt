#1274 - Receipt Scan → Auto-Create Expense
What & Why
Willard wants to snap a photo of a receipt and have the app automatically create the expense — no manual entry. The AI parsing backend already exists (POST /api/expense-import/parse-receipt handles images and PDFs and returns vendor, amount, date, category, description). What's missing is a dedicated UI flow that lets Willard upload a receipt first and have the expense form pre-filled from it, rather than creating the expense manually and then attaching a receipt as a second step.

Done looks like
A prominent "Scan Receipt" button on the Expenses page (top of the page, near the existing "Add Expense" button)
Clicking it opens a file picker (camera on mobile, file browser on desktop) — accepts JPG, PNG, HEIC, PDF
While the AI reads the receipt, a loading state ("Reading receipt…") is shown
The expense creation form opens pre-filled with extracted fields: vendor, amount, date, category, description
The receipt image is already attached to the form (user can see a thumbnail)
User can review and correct any field, optionally link to a job, then save
On save, the expense is created and the receipt is uploaded and stored in one action — the expense opens with receiptStatus = "uploaded" and the receipt thumbnail visible
If AI extraction fails (bad photo, unreadable receipt), the form still opens blank so the user can fill it in manually
Out of scope
NAS or Google Drive integration (future)
Batch scanning multiple receipts at once
Auto-matching receipts to bank transactions (future)
Work photos / job photos (separate feature)
Steps
"Scan Receipt" button on Expenses page — Add a "Scan Receipt" button next to the existing "Add Expense" button at the top of Expenses.tsx. Use a camera/receipt icon. The button triggers a hidden <input type="file" accept="image/*,application/pdf" capture="environment"> so mobile users get the camera and desktop users get a file browser.

AI parsing call and loading state — When a file is selected, POST it as multipart/form-data to /api/expense-import/parse-receipt. Show a loading overlay or spinner ("Reading receipt…") while the request is in flight. On success, proceed to step 3. On failure, proceed to the blank form (step 3) with a toast warning that extraction failed.

Pre-fill the expense form — Open the standard new-expense form (the existing modal/drawer already used for "Add Expense") with the AI-returned fields pre-populated: description, vendor, amount, date, category, notes. Also store the selected file in state so it can be uploaded on save. Show a receipt thumbnail preview inside the form.

Save with receipt in one action — On form submit, create the expense via the existing POST /api/expenses route (with all fields including receiptStatus: "uploaded"), then immediately upload the receipt file to POST /api/expenses/:id/receipt. If the receipt upload fails after a successful expense save, show a non-blocking toast ("Expense saved — receipt upload failed, open it to retry") rather than rolling back.

Job linking — Ensure the job selector in the pre-filled form is visible (it already exists in the expense form) so Willard can link the receipt to a specific job before saving.
