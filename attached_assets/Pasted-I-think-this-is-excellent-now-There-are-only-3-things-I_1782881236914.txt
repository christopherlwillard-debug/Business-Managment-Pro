One Small Wording Change

This sentence:

Apply Pricing builds a draft invoice...

I'd change to:

Apply Pricing creates or updates a draft invoice for the current job. If a draft invoice already exists, the office may choose to overwrite it with newly calculated pricing or keep the existing invoice. Once an invoice has been finalized or marked as sent, Apply Pricing must not overwrite it automatically.

That protects you from accidentally wiping out edits after someone has already started working on an invoice.

Overall

I honestly think this is one of the better specifications you've put together.

It follows a clean architecture:

Job Card → Records the work.
Production Billing Catalog → Defines billable items and default pricing.
Client Production Pricing → Overrides pricing where needed.
Pricing Engine → Builds invoice line items.
Invoice → Snapshot that can be edited without affecting future jobs.

The only changes I'd make are:

Remove the Client Type requirement and let the job type determine which pricing engine runs.
Treat Billing Types as application-defined values rather than user-managed seed data.
Add a Display Order field so invoices always appear in a logical sequence.
Protect existing draft/finalized invoices from being unintentionally overwritten by a second Apply Pricing action.

Those four changes would make the design even more robust without adding much complexity.

The Job Type.

The Client.
