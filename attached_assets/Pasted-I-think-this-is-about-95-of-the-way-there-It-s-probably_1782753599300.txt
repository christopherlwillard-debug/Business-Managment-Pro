I think this is about 95% of the way there. It's probably the version I'd hand to Replit. There are only a handful of things I'd tweak because they affect how you'll use it every day.

1. Don't store the guide ID on the job

Right now you're storing:

Dealer Price
Quoted Price

That's perfect.

I'd also store:

Pricing Guide Name

Dealer Guide

or

My Pricing

instead of only an ID.

Why?

If you later delete or rename a guide, the job still tells you:

This job was priced using Dealer Guide

without relying on a foreign key that may no longer exist.

2. "Reset to Guide" needs a warning

This button can destroy work.

I'd specify:

If manual estimate edits exist, show a confirmation dialog:

This will replace all Manufactured Home generated line items with the current guide pricing. Custom line items will be preserved.

That's a huge difference.

You don't want someone losing a custom sewer line item because they clicked Reset.

3. Preserve custom estimate items

This is probably the biggest thing I'd add.

Imagine the wizard creates:

Trim Out

Plumbing

Travel

Then you manually add

Skirting Repair

When you click

Update Pricing

it should update only the Manufactured Home generated items.

NOT

Delete everything

Recreate estimate

I'd even tag generated items internally.

Example:

generatedBy

MFH

Then Update Pricing knows exactly what it owns.

4. Let add-ons be model defaults

Today you'll probably check

Plumbing Under Home

80% of the time.

Instead of checking it every job,

let the model say

Southern Farmhouse

Default Add-ons

✓ Plumbing

✓ Vinyl Ends

☐ Travel

When you pick the model, they're already selected.

You can still uncheck them.

5. Separate dealer pricing from your pricing

Instead of

Dealer Guide

My Pricing

I'd actually show

Dealer Cost

$1500

My Price

$1750

Profit

+$250

That's valuable information while you're creating the job.

6. Auto-detect construction

This is just a UI thing.

Instead of showing

Construction

VOG

I'd make it obvious.

Southern Farmhouse

🏠 VOG

or

Construction

VOG

(auto)

So it's clear it isn't editable.

7. Biggest thing I'd add

Every model should have Notes.

Example:

Southern Farmhouse

Notes

Use 2x4 marriage trim

Needs 8' porch flashing

Clayton bulletin 22

Those little things save enormous amounts of time over the years.

8. Future proof the library

I'd add two optional fields to every model:

Introduced

2024

Discontinued

(blank)

You already have Active/Inactive.

This just gives you historical context later.

My only architectural suggestion

I would not call the endpoint:

POST /jobs/:id/mfh/apply-defaults

because it's doing much more than defaults.

It's:

applying benchmark
applying checklist
creating estimate
saving pricing snapshot

I'd call it something like:

POST /jobs/:id/mfh/configure

or

POST /jobs/:id/mfh/apply

"Defaults" undersells what it's doing.

Overall

This has evolved into something much better than the original wizard idea.

It now feels like a natural extension of the Job Card rather than another standalone feature.

The only functional additions I'd make are:

Preserve manually added estimate line items when updating/resetting pricing.
Tag generated estimate line items so the system knows which ones it owns.
Allow default add-ons to be defined per model.
Add a confirmation dialog before resetting generated pricing.
Store the pricing guide name (or snapshot it) alongside the prices for historical context.

With those additions, I think this becomes one of the strongest workflow features in your app because it automates everything you repeatedly do while still letting you customize each job when needed.
