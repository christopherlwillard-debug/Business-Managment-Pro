This version of #806 is significantly better than the earlier versions. Looking at the uploaded spec, you've effectively turned it from a "Services Card Editor" into a true builder primitive.

A few things stand out as especially strong:

Keep

✅ CardComponent registered as a builder-wide primitive

✅ Templates and Presets separated

Templates = content structure

Presets = visual styling

That's exactly how professional builders handle it.

✅ Theme inheritance using null = inherit

This will save you massive headaches when Theme Designer (#723) lands.

✅ Trust Card instead of Certification Card

This broadens the audience beyond contractors while still supporting your SBA/Veteran-owned use cases.

✅ Analytics hooks reserved now

Smart move. You don't need analytics today, but you'll be glad those fields exist later.

✅ Visibility rules reserved now

Also smart. Seasonal promotions, financing offers, and holiday specials become possible without future schema migrations.

One thing I'd still add
Card Collections as a real future roadmap note

Right now you reserve the name:

CardCollection

I'd expand the comment slightly:

// CardCollection — future container for card-based sections.
// Examples:
// Team Section -> CardCollection<CardComponent>
// Pricing Section -> CardCollection<CardComponent>
// Portfolio Section -> CardCollection<CardComponent>
// Testimonial Section -> CardCollection<CardComponent>
//
// CardComponent is the primitive.
// CardCollection is the container.

That tells future developers exactly where you're headed.
