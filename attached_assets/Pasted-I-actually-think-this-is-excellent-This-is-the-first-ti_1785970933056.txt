One thing I'd add

I wouldn't stop at Rule 31.

I'd add one final rule.

RULE 32 — Verify With Real Data Before Closing

Regression tests and synthetic test data are required, but they are not sufficient.

Before closing a bug:

1. Verify the fix using real application data.
2. Confirm the expected behavior in the actual UI.
3. Confirm no existing user data was affected.
4. Compare the result against the original bug report.
5. Only then may the issue be marked complete.

A bug is not considered fixed until it has been verified against real-world data.
Why?

Everything Replit tested was synthetic test data.

Real-world data often uncovers edge cases that test records don't.
