The only major thing I'd add before calling #806 finished is:

Make CardComponent a Builder-Wide Primitive

Right now the task says:

Services uses CardComponent now, other sections migrate later.

I would make that explicit:

Additional Architectural Requirement

CardComponent is promoted to a first-class builder primitive alongside:

Heading
Paragraph
Button
Image
Form
Map
Video

The component registry should register:

type = "card"

CardComponent becomes available inside:

Content Blocks
Row Columns
Services Sections
Future Team Sections
Future Pricing Sections
Future Portfolio Sections
Future Testimonial Sections

This prevents a second card implementation from appearing elsewhere in the builder.

All future card-based features must consume CardComponent rather than creating section-specific card types.

That one sentence can save months of technical debt later.
