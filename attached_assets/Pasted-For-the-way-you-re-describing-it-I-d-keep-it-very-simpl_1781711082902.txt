Exactly. I think this is where Replit is probably heading in the wrong direction.

A subcontractor's profile should only store information about the person:

Name
Phone
Email
Tax information
Default pay preferences (optional)
Active/inactive status

It should NOT store:

Hourly rate
Percentage split
Fixed amount
Profit allocation
Payment terms

Because those can change on every job.

I'd tell Replit:

Job-Based Compensation Structure

Compensation should be assigned at the JOB level, not the subcontractor profile level.

A subcontractor may be paid differently on every job.

Examples:

Job A

Dewayne = $25/hr
Chris = Owner
Worker 3 = 50% split

Job B

Dewayne = 33% split
Chris = 33% split
Worker 3 = 33% split

Job C

Dewayne = Fixed $500
Worker 3 = $30/hr

Because compensation changes by job, pay settings must be stored in the job assignment record, not in the subcontractor profile.

When Adding a Worker to a Job

After selecting a subcontractor, allow the user to choose:

Compensation Type:

Hourly
Percentage Split
Fixed Amount
Equal Split

Based on the selected type, show the appropriate fields:

Hourly

Hourly Rate
Hours Worked

Percentage Split

Percentage %

Fixed Amount

Fixed Dollar Amount

Equal Split

No additional fields needed
Database Design

Create job-specific compensation fields on the job_subcontractors table:

subcontractor_id
job_id
compensation_type
hourly_rate
hours_worked
percentage_split
fixed_amount
payment_status
paid_at

These values belong to the job assignment, not the subcontractor profile.

The same subcontractor should be able to have completely different compensation arrangements on different jobs without affecting past or future jobs.

That structure is how most contractor systems are built. The subcontractor record is the person. The job assignment record contains the deal you made for that specific job. That way Dewayne can be $25/hr on one manufactured home, 50% on the next, and a flat $500 on another without changing his profile every time.
