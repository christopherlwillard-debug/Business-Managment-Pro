I would make one small change

Verify Builder Activation/Deactivation Works Correctly

I'd rename it:

#1037 – Validate Builder Activation/Deactivation Behavior

"Validate" tells Replit this is an acceptance test, not new feature development.

I'd add one more test

Because this is something that will matter later.

Model behavior

After a builder is deactivated:

Existing models remain attached.
Models cannot be selected on new jobs because the Builder is inactive.
Reactivating the Builder immediately restores all associated models.

That explicitly tests the Builder → Model relationship.

One more edge case

I'd add this:

Attempting to deactivate a Builder that is the only active Builder should still succeed. The application should continue to function normally and allow the Builder to be reactivated later.

It seems obvious, but you'd be surprised how often software accidentally assumes "there's always at least one active Builder."
